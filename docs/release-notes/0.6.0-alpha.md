# 0.6.0-alpha: role-based write access

Env var names: the OSS build reads `COLA_REGISTRY_*`. The CDT build (`make build-all PREFIX=cdt`, binaries `cdt-registry` / `cdt-regctl`) reads the same settings with the `CDT_REGISTRY_` prefix, for example `CDT_REGISTRY_ADMINS` and `CDT_REGISTRY_REQUIRE_MAINTAINERS`. Flags are the same in both builds.

---

## Before you upgrade

Nothing changes for writes until you set server admins. Read these checks first anyway, because two fixes change API behaviour for every deployment (PUT, principal validation).

1. **PUT is now a partial update.** On `PUT /api/v1/registry/{name}` and `PUT /api/v1/registry/{name}/package/{package}`, a field you omit (or send as `null`) now keeps its stored value. Before, it was cleared. An explicit empty value (`[]`, `{}`, `""`) still clears. Any client that relied on "omit to clear" must now send the empty value. `name` is optional in PUT bodies; if you send it, it must match the URL (400 otherwise).
2. **Role lists are validated.** In a POST or PUT body, each element of `admins` and `maintainers` must be a single principal: not empty, no comma, no whitespace. A body with any other element is rejected with 400, and the error names the field and the first bad element. Stored lists are not re-checked: a PUT that does not send the list still succeeds.
3. **Fix role data before you turn roles on.** Existing `admins` (registry) and `maintainers` (package) entries take effect as soon as enforcement is on. Matching is exact and case-sensitive against the caller's username and groups. An entry written as an email (`first.last@example.com`) does not match an authenticator that reports a uid (`first.last`): rewrite those entries first.
4. **Audit lines ignore `logging.level`.** Every authenticated write now logs a `Write audit` line on stdout at Info, even with `--log-level warn` or `error`. Expect more log volume on write-heavy servers.
5. **Publishing an existing version now returns 409** `VERSION_ALREADY_EXISTS`. It used to return 500 `STORAGE_UNAVAILABLE`. Alerts or scripts that keyed on that 500 need updating.

### Turning role enforcement on

Roles are opt-in. To turn them on, an operator must:

1. Run with an authenticator: `--auth-type` / `COLA_REGISTRY_AUTH_TYPE` must be `basic`, `ldap` or `custom_jwt`. With auth type `none`, the server ignores the admin list, allows every write and logs a warning at startup.
2. Set the server admins: `--admins` / `COLA_REGISTRY_ADMINS` (`CDT_REGISTRY_ADMINS` in the CDT build). The value is a list of usernames or groups, separated by commas, whitespace, or both, for example `CDT_REGISTRY_ADMINS="gu-cdt-maintainer, g-app-cdt-operator svc-jenkins"`. An empty or unset value keeps enforcement off.
3. Give registries their `admins` and packages their `maintainers` (`cola-regctl registry update --admin ...`, `cola-regctl package update --maintainer ...`). With enforcement on and empty lists, only server admins can create packages or publish versions in a registry.
4. Check the startup log: `Role enforcement is on` with `enforced=true` and the parsed `server_admins`. `cola-regctl whoami` shows `Server admin: yes` for a server admin.

With enforcement on, a write without the needed role gets **403 `FORBIDDEN`** ("requires <role> on <scope>"), and the CLI exits with code 6. A write without valid credentials still gets 401. `REQUIRED_GROUP` (custom JWT and LDAP) is unchanged and still applies before the role check.

| Write | Lowest role that may do it |
|---|---|
| create or delete a registry | server admin |
| update a registry; create or delete a package | registry admin (the registry's `admins`) |
| update a package; publish or delete a version | package maintainer (the package's `maintainers`) |

A higher role holds every right of the roles below it. See ADR 0001, `docs/adr/0001-role-based-write-access.md`.

To roll back, unset the admin list (or set it empty) and restart. The data is not changed.

## What's changed

### Role-based write access (ADR 0001)

- **Server-admin setting and `whoami`.** New `--admins` / `COLA_REGISTRY_ADMINS` setting: a non-empty list turns role enforcement on (unless auth type is `none`). `GET /api/v1/whoami` returns `server_admin` (true only when enforcement is on and the caller is in the list), and `cola-regctl whoami` prints it as `Server admin: yes|no` (and `server_admin` in JSON). (`6673193`, `06-server-admins-setting-and-whoami`)
- **Roles enforced on registry writes.** Creating or deleting a registry needs server admin. Updating one needs registry admin. A denied write gets 403 `FORBIDDEN`. The role check runs under the storage lock, after the 404 check and before 409. (`8c0bc39`, `07-enforce-roles-on-registry-writes`)
- **Roles enforced on package and version writes.** Creating or deleting a package needs registry admin. Updating a package and publishing or deleting a version need package maintainer. (`95ff081`, `08-enforce-roles-on-package-and-version-writes`)
- **Write audit log.** Every authenticated write that reaches storage logs one `Write audit` line on stdout. The line carries `caller`, `action`, `target`, `decision` (`allow`/`deny`), `enforcement` (`on`/`off`) and `matched_role`/`missing_role`. Writes that set a role list also log `old_admins`/`new_admins` or `old_maintainers`/`new_maintainers`. No tokens or groups are logged. (`8c0bc39`, `95ff081`)
- **Audit lines ignore the log level.** Audit lines go through their own logger, which uses the server's output and format but stays at Info whatever `--log-level` / `logging.level` says. (`4465fcd`, `19-audit-always-visible`)
- **Principal format.** `admins`/`maintainers` elements that are empty or contain a comma or whitespace are rejected with 400. The CLI `--admin` and `--maintainer` flags accept comma- and/or space-separated lists, are repeatable, and their help says "user or group" (the flag type label changes from `strings` to `stringArray`). (`76b03a3`, `05-principal-list-validation-and-parsing`)
- **Opt-in required maintainers.** New `--require-maintainers` / `COLA_REGISTRY_REQUIRE_MAINTAINERS` (`CDT_REGISTRY_REQUIRE_MAINTAINERS`), default off and independent of role enforcement. With it on, creating a package with no maintainers, or a PUT that sets `"maintainers": []`, returns 400 ("the server requires at least one maintainer"). A PUT that omits `maintainers` is still allowed. A value that is not a boolean (for example `maybe`) stops the server at startup. (`414c207`, `870ecec`, `12-require-maintainers-option`)

### Fixes

- **PUT keeps omitted fields.** Registry and package PUT are partial updates: an omitted or `null` field keeps its stored value, and `[]` / `{}` / `""` clears it. `name` is optional and checked against the URL. The merge runs under the storage lock, and a package PUT keeps the package's versions. `cola-regctl registry update` and `cola-regctl package update` work again (they always failed with 400 before), and `--clear-admins` / `--clear-maintainers` still clear. OpenAPI documents the semantics and adds the package PUT. (`ebaee18`, `04-put-keeps-omitted-fields`)
- **Duplicate version returns 409.** Publishing a version that already exists returns 409 `VERSION_ALREADY_EXISTS`, as documented, instead of 500 `STORAGE_UNAVAILABLE`. (`6d2e3ae`, `08-enforce-roles-on-package-and-version-writes`)
